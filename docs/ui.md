# In-game menu

The side-panel menu at the top right: `Game.js` `OnGUI` from "Basic Setup", `GUIPanel()`, and the `Settings.js` panel dialogs (`showDialogServer()`, `showDialogGame()`, `showDialogPlayer()`, `showDialogPlayers()`). The `Settings.js` `OnGUI` that drew an older `showBox` menu is commented out in the source and is not ported.

## Side panels and Server Settings (2026-10-23)

Ported into `Game.cs` and `Settings.cs`:

- `GUIPanels`, with the values decoded from the original binary `Game.unity`: Server Settings, Game Settings, Player Settings and Active Players (active, closed, minimum height 250), Switch Vehicle (inactive, open, bold, 250–350) and Settings Advisor (inactive, open, bold, 155–160).
- The layout: closed panels are 25 px buttons in a 170 px column 180 px from the right edge; open panels share the remaining height (Screen.height − 60) between their minimum and maximum, easing at 3 × dt; the oldest open panel closes after 1.5 s of overflow. Game Settings' button shows the frame rate. Each panel window has the skin's `close_button` and a scroll view.
- The `<<` / `>>` button at the bottom right toggles `Settings.simplified`, which hides the panels.
- `Game.Skin` is the original `Mars GUI` skin, now bound in `Game.unity`.
- `Settings.showDialogServer()`: the host branch, in the original order and with the original ranges and labels, limited to what the port honours: Minimap enabled; Lasers enabled, L Hits Rematerialize, Lsr Spd (an `int`, as in the source), Lsr Gvt, Lsr Rco; Gravity (now applied to `Physics.gravity` in `updatePrefs`); Visibility; Sea Vis and Sea Alt when the world has a sea (Sea Alt now moves `World.sea`); Bots: Can Fire, Can Drive, Add Bot, Axe Bot; Buggy: Stall Blending, Powered Loops, Smart Suspension, Fl Speed, Fl Agility, Stability, Power, Speed, Traction, Shocks, Firepower, Lsr Lck. `updateServerPrefs()` applies the settings locally; there is no server offline.

Left out: the online settings (Default All, server name, listing, password, welcome message, networking, settings I/O, nTime), Camouflage Badges (name tags are not ported), XORBs (RORBs were added on 2026-11-02), and the hovercraft, tank and jet sections. Game Settings, Player Settings and Active Players were ported on 2026-11-19 (below). Switch Vehicle and Settings Advisor are never switched on yet. The Exit Game button, the HUD hint lines and the GUI fade (`GUIAlpha`) are not ported.

Engine difference: the skin's default font, Arial Rounded Bold, was imported as a static character set (`Unicode`). Unity 6 draws IMGUI text through TextCore, which cannot load a font face from a static font, so every Mars-skin string failed to generate. It logged "Unable to find a font file with the specified Family Name [Arial Rounded Bold]" every frame, and each button showed the last string drawn, the HUD readout. The font is now imported as Dynamic, as Ethnocentric already was. The importer rewrote the `.meta` in its current format, which reset character spacing and padding; those settings only affect static font textures.

Verified (Unity `6000.3.26f1` editor, macOS `27.0.1`, Play mode from `Init`): `tools/compile-check.sh` passes. On screen, the four panel buttons read Server Settings, Game Settings (with the frame rate), Player Settings and Active Players, and the `>>` button shows. Opened through the Unity MCP, Server Settings showed its window with Game Features, the laser rows, Gravity, Visibility and the start of Bots. The rest of the panel, and clicking Add Bot or any control by hand, were not checked: clicks into the editor were refused by the screen tool, and the editor then closed (no crash report). Add Bot itself is covered by `Run Bot Test`, which calls the same `Game.addBot()`.

Click test (2026-10-23, Unity `6000.3.26f1` editor, macOS `27.0.1`, Play mode from `Init` into Fort Boxy, driven by real mouse clicks): clicking Server Settings opened the panel; the scroll wheel scrolled it; with no bots only Add Bot showed. Add Bot logged "Player added a bot", Axe Bot appeared beside it, and "Player's bot" spawned after the 2 s delay and started firing (plasma sparks in the hierarchy). Axe Bot removed the bot, hid itself again, and the player "Defaulted to Quarry" (the bot had taken quarry). Can Fire unticked and ticked again. The Buggy section rendered to its last row (Lsr Lck), and the close button collapsed the panel back to its button. The bot's minimap marker was not seen in the one minimap capture; not checked further.

## Messaging Console (2026-11-17)

`Messaging.cs` now ports `Messaging.js` `OnGUI` and `ChatWindow`: the "Messaging Console" window at the top left (10, 40; a quarter of the screen wide, between 170 and 250 px; three quarters of the height when the minimap shows), its close button and collapsed button, the three message styles, the chat field, Tab to start or cancel, Enter to send, and the `r` and `x` chat commands. `Game` gained `kpDur` and `kpTime`. The temporary bare R and X hotkeys are removed. A chat line is only added locally and the language filter is not ported. `x` always answers "XORBs Unavailable" until XORBs are ported; `Settings` now zeroes `zorbSpeed` without RORBs as `Settings.js` does. The camera keys are ignored while chatting. Static only (`tools/compile-check.sh` passes, Unity `6000.3.27f1`, macOS `27.2.1`); focus handling in Unity 6 IMGUI has not been tried.

Checked 2026-11-18 (Unity `6000.3.27f1` editor, macOS `27.2.1`, Play mode from `Init`, Game view screenshots): the console window draws at the top left above the minimap with the welcome message, server messages centred, a local chat line on the left, the chat field and "(Press \"Tab\" to Message)". The `x` command answers "XORBs Unavailable". Typing, Tab and Enter by hand were not tried.

Tried by hand (2026-11-18, Unity `6000.3.27f1` editor, macOS `27.2.1`, Play mode from `Init`, real key and mouse events sent to the editor window): Tab opens the field, typing and Enter send a local chat line, `/r` starts the 10 s reset ("MarsRacer Resetting in 10 seconds...", vehicle frozen, then back at the base), and while chatting the camera keys and Space go into the field instead of the game. Two engine differences were found and fixed in `Messaging.cs`:

- Unity 6 does not report keys to `Input` while an IMGUI text field has keyboard focus, so Tab pressed while chatting reached only the GUI key event and never cancelled. The window now accepts the Tab key event as well as `Input.GetKeyDown`, and clears keyboard focus when it cancels.
- After Enter the field kept keyboard focus, which swallowed the next game key (a Space after sending did nothing). Enter now clears keyboard focus too.

Both rechecked by hand after the fix: Tab opens and cancels, and the first key after sending (5, Soar camera) acts at once.

## L Hit ORBs (2026-11-19)

Server Settings now shows "L Hit ORBs" between "Lasers enabled" and "L Hits Rematerialize" when lasers and RORBs are both on (`Settings.js:794`). It switches `lasersOptHit`, which `RocketModern` already honoured (`maskOpt`). The frame rate on the Game Settings button is now the original 2 s count (`Game.js:325-329`): frames over each 2 s divided by 2 with integer division, so it reads in whole steps and shows 0 or 1 for the first 2 s. The crosshair is drawn while chatting too, as `Game.js` drew it whenever the cursor was locked. Checked in Play mode from `Init` (Unity `6000.3.27f1`, macOS `27.2.1`): with RORBs and lasers on, the row showed in place and a real click ticked `lasersOptHit`; the button read "Game Settings (131 FPS)"; no console errors.

## HUD readout, filter and keys (2026-11-19)

Unity `6000.3.27f1`, macOS `27.2.1`. The speed, altitude and distance readout is back to `Vehicle.js`: a 150 px button centred at the bottom, speed from the rigidbody with "Static" below 0.05 m/s, and DST whenever the player is not quarry. The longest form ("3 MPH     1 ALT     123 DST") fits, checked on screen. Chat lines pass through `Game.js` `LanguageFilter` (its word lists are copied from the source). ## Game Settings, Player Settings and Active Players (2026-11-19)

`Settings.cs` now has `showDialogGame()`, `showDialogPlayer()` and `showDialogPlayers()`, called from `Game.cs` `DrawPanel` for panels 1 to 3 as `Game.js` `GUIPanel()` does. Each follows `Settings.js:257-675` in order, labels, ranges and the preference each control writes, limited to what the port honours:

- Game Settings: Enter/Exit Fullscreen (0); the resolution arrows (added the same day, below); Rendering Quality, Fastest to Fantastic with the frame rate, `<<` and `>>` (`renderLevel`); Visibility Cap, 200 to 1000 with 1000 shown as MAX (`viewCap`); FPS Cap, 10 to 100 with 100 meaning no cap (`targetFrameRate`, saved as the slider's unrounded float as in the source); Enable Minimap while the server allows it (`useMinimap`); Enable Settings Advisor (`showHints`, saved and loaded, though the Settings Advisor panel itself is not ported); the Audio section (added the same day, below).
- Player Settings: Reset My Position (/r), then "Reset In" with the countdown, hidden during the cool-down that follows, exactly as the `/r` command; Camera Mode Ride, Chase, Soar, Spectate and Roam (`cam`); GyRide Enabled (7) (`gyroCam`); HyperCam Enabled (`flightCam`); the Ride, Chase and Spectate/Roam notes; Chase Strategy Smooth, Agile, Arcade (`camChase`) and Chase Distance 0 to 20 (`camDist`); Vehicle Color with the quarry note, Randomize/Random Coloring, the body sliders (green capped by `Lerp(0.1, 0.8, (r + b) / 2)`, each resetting the accent) and the Accent Color sliders. A slider change sets `colorCustom` and recolours at once; `Game.Update` saves the colour (`vehCol*`, `vehColCustom`) 3 s after the last change, as `Game.js` does with `colorUpdateTime`.
- Active Players: each vehicle's name, with "(Me)" for the player, listed by name (the original iterates a `Hashtable`, so its order is arbitrary).

The fullscreen button behaves as the `0` key does, not as `toggleFullscreen()`, keeping the point-size resolution the IMGUI HUD needs (`IMPROVEMENTS.md`). Left out: the XORB button (XORBs are not ported), and in Active Players the joining-players list, Evict, Ban, the banned list and each player's network text box (ping, jitter, IP address and view ID), all online only. The original panel shows no scores, so none were added.

Verified (Unity `6000.3.27f1` editor, macOS `27.2.1`, Play mode from `Init` into Fort Boxy, real clicks sent to the Game view): `tools/compile-check.sh` passes and the console stayed free of errors and warnings. Game Settings: `<<` went from Fantastic to Beautiful with both arrows then showing; the Visibility Cap slider read 538 and the fog closed in; the FPS Cap slider read 40 and the button then showed about 40 FPS; Enable Minimap hid the minimap and the Messaging Console grew to fill the height, and ticking it again brought both back. Player Settings: Chase, Roam (the readout read STATIC as the roam camera took over) and Arcade switched; GyRide and HyperCam ticked and unticked; the chase distance slider moved the camera back; the Red slider turned the button into "Random Coloring" and lowered the accent to red − 0.25; Randomize Coloring restored the label; Reset My Position counted down from 10, broadcast "Resetting in 10 seconds...", returned the buggy to the base and hid the button for the cool-down. After a bot was added, Active Players listed "MarsRacer (Me)" and "MarsRacer's bot". The saved preferences read back as `renderLevel` 5, `viewCap` 538.46, `targetFrameRate` 40.46, `camChase` 2, `camDist` 13.54, `gyroCam` and `flightCam` as toggled, and the colour keys equal to the live colour with `vehColCustom` 1, then 0 after Randomize. The quarry note was not seen (the bot took quarry first), Smooth, Ride, Soar, Spectate and the accent sliders were not clicked, and the panels were not tried in a player build.

Resolution arrows (2026-11-19, Unity `6000.3.27f1`, macOS `27.2.1`, arm64 development player on the built-in Retina display): Game Settings now shows the `Settings.js` resolution row, `<<`, the current size and `>>`, in a player or in fullscreen, stepping through `Screen.resolutions` by width as the source does. Measured in the player, the Unity 6 macOS player already lists resolutions at point size, and only one: `Screen.resolutions` was `1512x982`, with `Screen.dpi` 255, the screen and `currentResolution` `1512x949` and the window's backing size `3024x1898`. A first version halved the list for Retina, as `UsePointResolution` halves the start-up size; that stepped down to `756x491` and was removed. With the single mode, the row read "1512X949" with `>>` alone in fullscreen, and "1512X860" with `>>` alone in a window. `>>` shows because the mode is taller, and changes nothing because the source steps by width only; that is the source's own logic, kept. `<<` and an actual size change could not be tried, as this display lists no other mode; an external display with several modes has not been tried. No exceptions in the player log.

## Audio: music, sound effects and HyperSound (2026-11-19)

Audit row S2, with the Game Settings Audio section from `Settings.js:375-407`: Sound Effects Enabled (`useSfx`), No Music, Classic, Ambient and Carefree (`useMusic` 0 to 3) and HyperSound (`useHypersound`), each saving its preference as the source does. Only the music toggles and HyperSound call `updatePrefs()`; the sound-effects toggle applies to sounds that start afterwards, as in the source.

Read from the official 2.22 build's `level2` with UnityPy: `Settings.musicTracks` is Classic, Ambient, Carefree, and `gameMusic` is the AudioSource on the `Camera` object (disabled, no play-on-awake, volume 0.5, pitch 1, rolloff factor 0, looping). The Unity 6 `Game.unity` still had that source on the Camera (2D, the same values) but `gameMusic` was unbound; `Game.unity` now binds it and the three clips (a targeted text edit of the Settings block).

- Music (`Settings.js:1598-1607`, in `updatePrefs`): No Music disables and stops the source; otherwise it is enabled at pitch 1 with the chosen track and played if it is not playing. The port stops the source before changing the clip, so a newly chosen track always starts from its beginning.
- HyperSound (`CameraVehicle.js:37-39`, in `CameraVehicle.LateUpdate`): the music's pitch follows the player's speed, `Clamp(−0.5 + speed / 15, 0.8, 1.5)`; switching it off goes back to pitch 1 through `updatePrefs`.
- Sound effects (`SoundEffect.js`, which sat on `LaserAuto`, `LaserSnipe`, both `PlasmaSparks` prefabs and the unported `Entry Effect`): with sound effects off, `Settings.SoundEffect` stops and removes the AudioSource as each bolt and each set of sparks spawns (`CombatSystemModern.Fire`, `RocketModern`).

Verified (Unity `6000.3.27f1` editor, macOS `27.2.1`, Play mode from `Init` into Fort Boxy, real clicks on the Audio toggles, state read through the Unity MCP): with no saved preference the game started playing Classic (enabled, looping, volume 0.5, 2D). Ambient switched the clip and restarted it from the start; HyperSound held the pitch at 0.8 at 1.7 m/s and gave 1.1455 at 24.7 m/s, matching the formula; unticking it returned the pitch to 1; No Music disabled and stopped the source; Carefree started it again. With Sound Effects Enabled unticked, a bolt fired at the ground and its sparks had no AudioSource in any of the next 90 frames; ticked again, both had a playing source in every frame. All five preferences read back as clicked; no console errors or warnings. Not checked by ear, and not tried in a player build.
